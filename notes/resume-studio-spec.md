# Resume Studio — the owner's specification (verbatim, 2026-10-23)

The owner pasted the text below as the requirement for the next phase of JobPilot AI. The
design that maps it onto the existing codebase, the split into work streams and every
project-specific rule live in `notes/resume-studio-plan.md`; **the plan wins where the two

# Build an AI-Powered Resume Builder, ATS Optimizer & Job Application Assistant

Act as a senior full-stack engineer, AI product architect, and UI/UX designer. Inspect the existing codebase first and implement a polished, production-ready resume and job-application feature that integrates seamlessly into the current application.

Do not create a separate demo application. Follow the existing stack, architecture, design system, authentication, database conventions, and coding standards.

## 1. Add a Resume Section to the Sidebar

Add a dedicated **Resume** section to the main sidebar.

The section should include:

- Resume Dashboard
- My Resumes
- Create Resume
- ATS Optimizer
- Job-Specific Resumes
- AI Model Settings
- Resume Version History

Use a clean, modern, responsive interface with an intuitive workflow and minimal friction.

## 2. AI Resume Creation

Allow users to create a professional resume from scratch or import an existing resume.

Supported inputs:
- PDF and DOCX uploads.
- Existing resume text.
- LinkedIn profile information, if users provide it through a supported import flow.
- User-entered personal, educational, and professional details.
- Work experience, projects, achievements, technical skills, certifications, and education.

Features:
- Offer professional, ATS-friendly templates.
- Generate concise, impactful experience descriptions.
- Convert responsibilities into achievement-oriented bullet points.
- Improve grammar, sentence structure, clarity, and professional tone.
- Highlight measurable impact without inventing metrics.
- Support software engineering, frontend, backend, full-stack, AI/ML, DevOps, and other job profiles.
- Provide a live resume preview.
- Allow section reordering, editing, deletion, and addition.
- Export to PDF and DOCX.
- Save drafts automatically and allow users to resume editing later.

Never fabricate experience, qualifications, employment history, certifications, or achievements.

## 3. ATS Resume Analyzer

Build an ATS optimization engine that evaluates a resume against a particular job description.

Allow users to paste a job description, upload it, or provide a supported job-posting URL.

Analyze:

- Relevant skills and keyword coverage.
- Job title and role alignment.
- Required versus preferred qualifications.
- Technical skill coverage.
- Experience relevance.
- Achievement quality.
- Resume readability and formatting.
- Section completeness.
- Potential parsing issues.
- Missing or weak evidence for job requirements.

Display:
- Overall ATS compatibility estimate.
- Category-wise scores.
- Matched keywords.
- Missing keywords.
- Weak or irrelevant content.
- Specific recommendations.
- Before-and-after bullet comparisons.

Make the scoring methodology transparent and configurable. Clearly label the result as an estimated compatibility score, not the actual score generated by a specific employer's ATS. Never guarantee shortlisting or employment.

## 4. Automatically Apply Resume Improvements

For every recommendation, offer:

- Apply suggestion.
- Ignore suggestion.
- Edit manually.
- Apply all safe suggestions.
- Preview changes before accepting.
- Undo and restore previous versions.

When users choose Auto-Optimize, generate an improved resume using the selected job description and their verified profile data.

Preserve the original resume and create a new version instead of overwriting the user's work.

Automatically rerun the analysis after accepted changes and show the updated estimated compatibility score.

Never add a missing skill or claim unless the user confirms it is accurate.

## 5. Role-Specific Resume Profiles

Users should be able to maintain different resume versions for different roles.

Examples:
- Full Stack Developer
- React Developer
- Node.js Backend Developer
- AI Engineer
- DevOps Engineer
- Software Engineer

Create a reusable master profile containing verified user information. Generate tailored resume versions from that profile without duplicating or corrupting the original data.

Allow users to:
- Select a target role.
- Enter a job description.
- Choose relevant projects and experiences.
- Prioritize role-specific skills.
- Compare versions.
- Track changes between versions.
- Rename, duplicate, archive, and restore resumes.

Keep every version linked to the original source data and record which changes were AI-generated or manually edited.

## 6. Company-Specific Resume Intelligence

Add a company and job-targeting workflow.

When a user enters a company name, target role, and optionally a job-posting URL:

1. Retrieve relevant information using supported, reliable data sources.
2. Identify the actual job requirements whenever a specific vacancy is available.
3. Analyze the role's required skills, qualifications, responsibilities, and keywords.
4. Use verified company information only when relevant and available.
5. Tailor the resume toward the specific opportunity.
6. Save a company-specific version with the job title, source URL, date analyzed, and relevant job-description snapshot.
7. Explain which resume changes were made and why.

If the company has multiple open positions, ask the user to choose the relevant role instead of guessing.

Do not invent company requirements or claim to have current hiring information without retrieving it from a reliable source. If current information is unavailable, ask the user to provide the job description.

Support refreshing a saved job target when its job description or requirements change.

## 7. Multi-Provider AI Model Integration

Build an AI Provider Settings page where users can configure their preferred AI provider.

Support a provider-adapter architecture for:

- OpenAI API, including compatible GPT models.
- Google Gemini API.
- Anthropic Claude API.
- A configurable local or self-hosted model, where supported.

The UI should allow users to:

- Select an AI provider.
- Enter their own API key.
- Choose from supported models.
- Set a default model for resume generation.
- Choose a different model for ATS analysis or rewriting.
- Test the connection.
- View connection status and actionable errors.
- Set a fallback provider, if configured.
- Remove or rotate credentials.
- See estimated usage and costs where reliable usage data is available.

Fetch available models from provider APIs where supported. Otherwise, use a maintained model registry and validate model availability before use.

Do not assume that a ChatGPT Plus, Gemini subscription, or Claude subscription automatically includes API credits. Explain that API access and billing may be separate. Use supported API credentials or official authorization flows rather than attempting to reuse website login sessions or subscription cookies.

### Security requirements

- Never hardcode API keys.
- Never expose secret keys in frontend bundles.
- Never return stored secrets to the browser after saving.
- Encrypt stored credentials using an appropriate server-side key-management strategy.
- Mask credentials in the interface.
- Never log secrets or include them in error messages.
- Enforce user-level access control and authorization.
- Support credential deletion and rotation.
- Apply rate limits and reasonable usage controls.
- Validate provider responses and handle timeouts, quota errors, invalid credentials, and unavailable models.
- If secure credential storage cannot be implemented in the existing architecture, provide a safe session-only alternative rather than storing plaintext secrets.

Use each provider's official API and supported SDK. Keep provider-specific implementations behind a common interface so new models can be added easily.

## 8. AI Model Selection for Each Workflow

Let users configure different models for different tasks.

Example configuration:

- Resume creation: selected generation model.
- ATS analysis: selected analysis model.
- Bullet rewriting: selected writing model.
- Job-description analysis: selected analysis model.
- Final resume review: selected quality-check model.

Allow a user to override the default model for an individual task.

Provide a unified interface such as:

generateResume()
analyzeResume()
optimizeResume()
analyzeJobDescription()
tailorResumeForRole()
reviewResume()

Route these operations through the selected provider adapter.

If a configured model fails, show the error and let the user retry or select a fallback. Do not silently switch providers in a way that could incur unexpected costs or transmit user data to an unapproved service.

## 9. Job Application Workspace

Integrate the resume functionality into a broader job application workflow.

Allow users to save job opportunities with:

- Company name.
- Job title.
- Job description.
- Job-posting URL.
- Location and work arrangement.
- Required skills.
- Application deadline, if known.
- Selected resume version.
- Application status.
- Notes and follow-up dates.

Suggested statuses:
- Saved
- Preparing Resume
- Ready to Apply
- Applied
- Interview
- Offer
- Rejected
- Archived

For each job, show the tailored resume, estimated ATS compatibility, missing requirements, and application notes.

Allow users to track which resume version was submitted to which company.

Implement external job-application automation only through permitted, supported integrations. Never bypass CAPTCHAs, access controls, or platform restrictions. Require user review and confirmation before submitting applications or sharing personal information.

## 10. Resume Dashboard

Create a useful dashboard with:

- Total resumes.
- Recently edited resumes.
- Saved job opportunities.
- Resume versions needing review.
- Recent ATS analyses.
- Job-specific resume progress.
- Quick actions to create, import, optimize, and tailor a resume.

Include searchable and filterable resume lists, loading states, empty states, error states, confirmation dialogs, and helpful onboarding.

## 11. UI/UX Requirements

Build a premium, modern interface consistent with the existing product.

Prioritize:
- Clear typography and visual hierarchy.
- Responsive desktop and mobile layouts.
- Accessible forms and keyboard navigation.
- A split-screen resume editor and preview where appropriate.
- Side-by-side original and optimized content.
- Clear explanations of ATS findings.
- Non-blocking save states.
- Meaningful progress indicators.
- Useful tooltips for AI settings.
- Clear distinctions between verified facts, AI suggestions, and user-approved changes.

Avoid unnecessary complexity, decorative dashboards without useful data, and excessive modal dialogs.

## 12. Data Model and Backend

Design the data model according to the existing database and ORM.

Consider entities for:
- User profile.
- Resume.
- Resume section.
- Resume version.
- Verified user facts.
- Job target.
- Job description snapshot.
- ATS analysis.
- Optimization suggestion.
- AI provider configuration.
- Secure provider credentials.
- Job application.
- Application activity history.

Use proper ownership relationships, indexes, validation, migrations, and transaction handling where appropriate.

Store resumes in a structured representation so the content can be edited, analyzed, versioned, and exported reliably. Keep document rendering separate from AI generation.

Use asynchronous jobs for expensive operations where justified, with progress tracking and safe retry behavior.

## 13. Quality, Privacy, and Testing

Implement:
- Authentication and authorization checks.
- Input validation.
- Secure file uploads and document parsing.
- Protection against prompt injection inside uploaded resumes and job descriptions.
- Privacy-conscious logging and retention.
- Rate limiting and cost controls.
- Unit tests for scoring, transformations, and provider adapters.
- Integration tests for resume workflows and access control.
- UI tests for creation, editing, optimization, model selection, and version restoration.
- Graceful handling of malformed documents and provider failures.

Treat uploaded resumes and job descriptions as untrusted data. Do not allow instructions inside those documents to override system behavior or trigger unrelated tool actions.

## 14. Implementation Strategy

Before coding:

1. Inspect the current repository, framework, routing, sidebar, design system, authentication, database, and existing AI integrations.
2. Identify reusable components and existing conventions.
3. Propose a concise implementation plan and data model.
4. Identify any external services, environment variables, and dependencies needed.

Then implement the feature end-to-end, including the UI, backend, database migrations, AI adapters, security controls, and tests.

Do not stop at mockups or static UI. Core workflows should work with real persistence and real provider calls when credentials are configured.

Do not rewrite unrelated modules or break existing features.

If a provider or external integration cannot be fully configured in the environment, implement the integration interface, document the required configuration, and clearly identify what remains.

## 15. Definition of Done

The feature is complete when a user can:

1. Open Resume from the sidebar.
2. Create a resume or import an existing one.
3. Edit and export it.
4. Analyze it against a real job description.
5. Review and apply safe AI suggestions.
6. Compare the original and optimized resume.
7. Create different versions for different job roles and companies.
8. Configure their own supported AI provider and select a model.
9. Save and revisit their resumes, analyses, and job targets.
10. Track job applications and their associated resume versions.
11. Use the feature securely with clear errors and no fabricated information.

Deliver a working, maintainable implementation with a concise summary of files changed, architectural decisions, setup instructions, database migrations, environment variables, and test results.

**Start by inspecting the existing codebase. Then implement the feature using the existing project conventions.**
